# 东北刨幺414 微信小程序 — 设计文档

**日期**：2026-03-21
**项目**：东北刨幺414 微信小程序
**技术方案**：方案 B — 阿里云轻量服务器 + Node.js 后端

---

## 一、项目概述

开发一款微信小程序形式的扑克游戏"东北刨幺414"，支持6人联机对战（3v3）。面向东北地区扑克爱好者，风格活泼高级。

### 核心目标
- 支持好友联机（房间码）与陌生人快速匹配
- 完整实现414游戏规则（路数系统、幺炸、借光等）
- 测试阶段支持AI机器人补位
- 全横屏显示，统一视觉风格

## 二、游戏规则摘要

### 基本设定
- **人数**：6人，隔一家为队友，形成3v3
- **牌数**：3副扑克共162张
- **分牌**：5=5分、10=10分、K=10分，总分300分
- **抓分**：每轮牌面最大的一方获得该轮所有分牌
- **出牌**：每位玩家出牌时有20秒的时间限制
- **牌局**：一局游戏结束后全部玩家点完准备按钮开始进行下一局
- **操作规则**：手牌中的卡牌分为上下两个区域，拖拽下半区时可以改变牌的位置，点击上半区时是选中某一张牌、滑动上半区可以连续选中多张牌

### 路数系统（牌型）
| 路数 | 牌型 | 说明 |
|------|------|------|
| 1路 | 单张 | 大王>小王>3>2>A>K>Q>J>10>9>8>7>6>5>4 |
| 2路 | 对子 | 两张相同点数 |
| 3路 | 顺子 | 3张+连续点数，最多到A；同张数比大小 |
| 4路 | 双龙 | 3对+连续对子，最多到AA；同对数比大小 |
| N路 | 炸弹 | N张相同点数（N≥3） |
| 特殊 | 幺 | 1张A + n张4（n≥2），每张4算2路 |
| 特殊 | 王炸 | n王（n≥2）（大王=2.5路，小王=1.5路） |

**相同路数优先级**：幺 > 王炸 > 普通炸弹/牌型（按点数比较）

### 借光规则
玩家A走完最后一手牌后，可借光给下一位队友：
- 若对方能管上A的最后一手牌 → 对方继续出牌
- 若对方阵营均不要 → A的下一位队友出牌

### 胜负与积分
**胜负判定**（满足任一条件）：
1. 第一个走完牌的玩家所在阵营积分 ≥ 135分
2. 非第一个走完牌的阵营积分 ≥ 210分
3. 以上均不满足 → 先走完全部3人手牌的阵营获胜

**累计积分**：
- 正常：胜方 +5，败方 -5
- 败方 ≤ 40分：败方 -20 （显示小血特效）
- 败方 ≤ 10分：败方 -50 （显示大血特效）
- 牌局解散时累计积分清零

## 三、技术架构

### 总览
```
微信小程序（前端）
    ↕ HTTP REST（登录、用户、房间管理）
    ↕ WebSocket（实时游戏对战）
阿里云轻量应用服务器（后端）
    ├── Node.js + Express   → REST API
    ├── Socket.io           → 实时通信
    └── MongoDB             → 数据持久化
微信服务器
    └── 提供 code → openid 登录凭证
```

### 技术栈
| 层级 | 技术选型 |
|------|---------|
| 小程序前端 | 微信原生小程序（WXML/WXSS/JS） |
| 后端框架 | Node.js 18 + Express 4 |
| 实时通信 | Socket.io 4（WebSocket） |
| 数据库 | MongoDB 6（Mongoose ORM） |
| 服务器 | 阿里云轻量应用服务器（Ubuntu 22.04） |
| 进程管理 | PM2 |
| HTTPS | Let's Encrypt（Certbot） |

## 五、数据模型

### User（用户）
```
_id         ObjectId
openid      String      微信唯一标识
nickname    String      昵称（最长12字）
avatar      String      头像URL（微信默认或自定义）
totalScore  Number      累计积分（默认0）
createdAt   Date
```

### Room（房间）
```
_id         ObjectId
roomCode    String      6位房间码（大写字母+数字）
status      String      waiting | playing | finished
seats       Array[6]    座位列表（userId / null / "bot"）
teamA       [0,2,4]     座位索引
teamB       [1,3,5]     座位索引
createdAt   Date
```

### Game（对局）
```
_id         ObjectId
roomId      ObjectId
deck        Array[162]  洗好的牌（服务端维护，不下发）
hands       Object      {userId: [cards]}（每人手牌）
scoreA      Number      A队当前局积分
scoreB      Number      B队当前局积分
currentTurn String      当前出牌玩家userId
lastPlay    Object      {userId, cards, type}
status      String      playing | finished
winner      String      teamA | teamB
```

## 六、核心功能模块

### 6.1 认证模块
- 微信 `wx.login()` 获取 code
- 服务端用 code 换取 openid（调微信 API）
- 生成 JWT token，存入小程序本地 storage
- 支持修改昵称、上传自定义头像（存阿里云OSS或服务器本地）

### 6.2 房间模块
- **创建房间**：生成唯一6位房间码，创建者坐0号位
- **加入房间**：输入房间码，服务端校验后分配座位
- **快速匹配**：维护匹配队列，凑满6人自动创建房间
- **分享**：通过微信 `shareAppMessage` 传递房间码
- **AI机器人**：人数不足时，房主可手动添加机器人补位

### 6.3 游戏引擎（服务端）
- **发牌**：162张洗牌，每人27张，服务端持有，仅下发各自手牌
- **出牌校验**：服务端校验路数合法性（不依赖客户端）
- **抓分统计**：每轮结束后服务端统计5/10/K的分值
- **借光处理**：玩家走完牌时服务端自动触发借光逻辑
- **胜负判定**：服务端判断三种胜负条件，结算并更新累计积分

### 6.4 实时通信事件（Socket.io）
| 事件名 | 方向 | 说明 |
|--------|------|------|
| `room:join` | 客→服 | 加入房间 |
| `room:ready` | 客→服 | 准备就绪 |
| `room:update` | 服→客 | 广播房间状态变化 |
| `game:start` | 服→客 | 游戏开始，下发手牌 |
| `game:play` | 客→服 | 出牌 |
| `game:pass` | 客→服 | 不要 |
| `game:update` | 服→客 | 广播出牌结果、当前轮次、积分 |
| `game:end` | 服→客 | 游戏结束，下发结算信息 |
| `game:timeout` | 服→客 | 出牌超时（20秒），自动执行不要 |
| `game:ready_next` | 客→服 | 玩家点击下一局准备按钮 |
| `game:next_start` | 服→客 | 全员准备完毕，开始下一局 |
| `chat:send` | 客→服 | 发送快捷语句/表情 |
| `chat:message` | 服→客 | 广播聊天消息 |

### 6.5 AI机器人
- 规则型AI：按简单策略出牌（优先出单张/对子，持有炸弹时伺机而动）
- 仅用于测试，不保证博弈水平
- 机器人行为由服务端驱动，延迟 800ms 模拟真人思考

### 6.6 聊天与表情
- 预设东北特色快捷语句（约20条），例如：
  - "哎呀妈，整个大活儿！"
  - "你这玩意儿行不行啊？"
  - "没事，下局整回来！"
- 预设情绪表情包（约12个）：开心/得意/懊悔/震惊/加油等
- 聊天气泡展示在对应玩家头像旁，3秒后消失

## 七、UI设计规范

### 视觉风格
- **主题**：明亮活泼 + 高级感，对标国内主流手游扑克UI
- **背景**：樱花城市风景（渐变天空 + SVG城市剪影 + 粉色樱花树）
- **配色**：
  - 我方/队友：翠绿 `#3DDD84`
  - 对方：红色 `#FF5555`
  - 主色调：金色 `#FFD700` ~ `#FF8C00`
  - 背景：暖色天空渐变
- **字体**：ZCOOL XiaoWei（正文）+ Noto Serif SC（标题/徽章）
- **屏幕方向**：全部横屏（667×375 基准）

### 页面说明
| 页面 | 核心元素 |
|------|---------|
| 主页 | 游戏Logo、用户信息、3个主菜单按钮 |
| 等待室 | 两队6个座位卡片、房间码、分享按钮、准备按钮 |

### 操作规则
手牌区卡牌分为上下两个触控区域：
- **拖拽下半区**：改变该张牌在手牌中的排列位置
- **点击上半区**：选中/取消选中单张牌
- **滑动上半区**：连续划过多张牌，批量选中

## 九、关键约束与注意事项

1. **微信小程序要求**：后端必须使用HTTPS，域名需在微信后台白名单配置
2. **游戏逻辑服务端权威**：所有牌型合法性校验、积分计算必须在服务端完成，防止作弊
3. **手牌保密**：服务端只向每位玩家下发自己的手牌，不广播他人手牌内容
4. **断线重连**：玩家断线后保留座位60秒，重连后恢复游戏状态
5. **并发控制**：出牌操作需加锁，防止同一轮次多次出牌
